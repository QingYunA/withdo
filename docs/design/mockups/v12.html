v12 · 系统通知（#68）

现在只有「提醒到点」会弹系统通知。这一版加四种：agent 交回任务、agent 卡住、PR 检查没过、PR 合并，再在设置里加一个总开关。通知是 macOS 自己画的，app 能定的只有文字、声音、分组和点开去哪：所以这份稿子主要定这四样，外加什么时候发、什么时候不发。

一 · 五种通知长什么样

标题先说发生了什么，再说是哪件事；副标题是项目；正文是 agent 最后一句话或者原因。点开都是打开这件任务的检查器（现在提醒就是这样）。同一个项目的通知在通知中心里叠成一摞。

浅色
深色，以及一次来了好几条

10 秒内来了 3 条或更多，只弹一条汇总（下面那条），不刷屏；点开去「我的」页。少于 3 条照常一条一条弹。

二 · 规则

什么时候发、文字、声音。英文版同样的结构。

种类什么时候发标题 / 副标题 / 正文声音点开
Agent 交回新agent 汇报把任务改成「待审查」（review）的那一刻，每次只发一次「Claude Code 做完了：任务名」/ 项目 / 有 PR：「PR #12 等你审查」，没有：agent 的最后一句有任务检查器
Agent 卡住新agent 汇报把任务改成「已阻塞」（blocked）的那一刻「Claude Code 卡住了：任务名」/ 项目 / 它在等什么（next_step，没有就用 summary）有任务检查器
PR 检查没过新GitHub 轮询发现检查从通过变成失败（和「我的」页那一行同一个时刻）「PR #12 检查没过：任务名」/ 项目 / 「打开 PR 看看哪一项失败」有任务检查器
PR 合并新GitHub 轮询发现 PR 合并、任务自动完成「PR #14 已合并：任务名」/ 项目 / 「任务已自动完成」无（好消息，不用你动手）任务检查器
提醒到点不变：remind_at 到了，只发一次，app 关着的时候到点的下次打开补发「提醒：任务名」/ — / 项目名或「收件箱」有任务检查器

不发的情况：总开关关着；这件事是你自己在 app 里改的（比如你手动把任务标成已阻塞）；app 正在最前面并且你正看着「我的」页（那一行已经出现在眼前，不再打扰；app 在后台或者在别的页面照常发）。app 关着时发生的交回、卡住、PR 事件不补发，打开后在「我的」页能看到；只有提醒照旧补发。

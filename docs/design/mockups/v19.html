v19 · Agent 发来的页面链接（#76）

Agent 汇报时可以带上几个链接（它写的 HTML 报告、设计稿、本地页面）。链接挂在那条汇报上：检查器的动态里显示成一排小块，点开用默认浏览器；任务等你看、最新汇报带链接时，「Agent 交过来的」那一行多一个「打开页面」。app 里不渲染 HTML。

一 · 检查器的动态

两条汇报，各带链接

链接在汇报文字下面，一行放不下就换行。像素文件图标（accent 色）+ 标题，标题过长省略。没给标题时显示文件名（file://）或域名加路径末段（https://）。

悬停 / 文件找不到

悬停：accent 浅底，提示框显示完整地址（本地文件显示成 ~/… 路径）。本地文件不在了：图标和文字变灰，点击时提示「找不到这个文件」，不报错弹窗。

二 · 「Agent 交过来的」那一行

在等你看、最新汇报带链接：多一个「打开页面」，排在「打开 PR」前面

按钮打开最新那条汇报的第一个链接（其余的在检查器里）。没有 PR 的任务就是「打开页面」「收下」两个。卡住的任务不出这个按钮（它在等你回答，不是等你看）。窄的时候三个按钮挪到摘要下面一行，规则同现在的两个按钮。项目页 Agent 栏的行和看板卡片悬停时，按钮一样。

三 · MCP 和规则

report_progress 多一个参数

  
规则
    
    
  • 挂在汇报上：存在那条汇报里（迁移 011，reports.links，JSON），任务上不另存。
    • 
    
  • 一次最多 5 个；标题可省，最长 80 字。
    • 
    
  • 只收 https://、http://、file://（必须是绝对路径）。别的协议或格式不对：整条汇报照收，坏的链接丢掉，返回结果里告诉 Agent 哪个被丢了、为什么。
    • 
    
  • 打开：系统默认浏览器（file:// 交给系统按文件类型打开）。打开前不检查网络地址；本地文件在画的时候检查一次是否存在。
    • 
    
  • 不在 app 里渲染，不下载、不缓存页面内容。
    • 
    
  • 总结页导出：带链接的任务那一行后面加 [标题](地址)。
    • 
    
  • MCP 指引加一句：你写了报告页面、设计稿这类能打开的结果时，用 links 附在汇报上。
    • 
    
  • get_task 返回的汇报里带上 links。
